# 功能 5：麦克风拾音与音频播放 —— 开发计划

> 本文档是开发前的方案与任务清单，供评审。实际开工时按阶段推进，每阶段有独立验收标准。
> 状态：⏸ 待评审（硬件环境搭建中）

## 1. 需求原文

| 项目 | 内容 |
| ---- | ---- |
| Codec | ES8388（24bit，ADC + DAC 二合一，I2C 控制） |
| I2S 引脚 | BCLK=GPIO7，WS=GPIO16，DIN=GPIO17，DOUT=GPIO15，MCLK=GPIO6 |
| I2C 引脚 | SDA=GPIO4，SCL=GPIO5 |
| 采样率 | 输入 24 kHz / 输出 24 kHz |
| 功放使能 | GPIO42（高电平开启） |
| 耳机检测 | GPIO3 |
| 按键 | BOOT=GPIO0（按下说话、松开停止），音量加 GPIO48 / 减 GPIO47 |

## 2. 硬件资源核对

### 2.1 引脚冲突检查 —— 无冲突 ✅

| 用途 | 引脚 | 功能 |
| ---- | ---- | ---- |
| 已有 · LED | 1 | 网络状态指示（低电平点亮） |
| 已有 · TF 卡 | 2, 11, 12, 13 | SPI2（CS / MOSI / SCK / MISO），当前屏蔽 |
| 已有 · LCD | 39, 40, 38, 41 | CS / DC / RST / BL（数据线复用 11/12/13） |
| **新增 · I2S** | 6, 7, 15, 16, 17 | MCLK / BCLK / DOUT / WS / DIN |
| **新增 · I2C** | 4, 5 | SDA / SCL（ES8388 控制） |
| **新增 · 功放** | 42 | PA 使能，高电平开启 |
| **新增 · 耳机检测** | 3 | 插入耳机时为高电平 |
| **新增 · 按键** | 0, 47, 48 | BOOT / 音量- / 音量+ |

全部新引脚与现有功能无重叠。但有两个**strapping 脚**需要注意：

- **GPIO0（BOOT）**：上电时电平决定启动模式。作为按键使用没问题，但按键按下时上电会进下载模式，文档需注明。
- **GPIO3（耳机检测）**：JTAG 信号源选择脚。若外部有强上/下拉，可能影响启动。需确认板上的实际电路。

### 2.2 内存与存储

| 项目 | 现状 | 影响 |
| ---- | ---- | ---- |
| **PSRAM** | ❌ **当前未启用**（`sdkconfig.defaults` 里被注释） | ⚠️ 录音缓冲受限，见 §3.2 |
| 内部 RAM | WiFi + HTTP + LCD 帧缓冲占用后剩约 150~200KB | 装不下多秒音频 |
| Flash 余量 | 536KB（35%） | 引入 `esp_codec_dev` 约 +25~35KB，绰绰有余 |

24kHz / 16bit / 单声道 = **48 KB/s**。这意味着：
- 内部 RAM 只能录 **约 3~4 秒**
- 录 30 秒需要 **1.44MB** → 必须用 PSRAM 或 TF 卡

### 2.3 依赖组件

`esp_codec_dev`（含 ES8388 驱动）**不在 IDF v6.1 内置组件里**，需单独引入。两种方式：

| 方式 | 做法 | 优缺点 |
| ---- | ---- | ---- |
| A. 组件管理器（推荐） | 加 `main/idf_component.yml`：`espressif/esp_codec_dev: "^1.6"` | 社区惯例、版本可控；需首次构建时联网 |
| B. 本地内置 | 从 xiaozhi 的 `managed_components/` 复制到 `components/` | 离线可构建；仓库体积 +1.1MB |

> 你本地已有 xiaozhi 的完整副本（`espressif__esp_codec_dev` v1.6.2），方式 B 可直接复用。
> 考虑到本项目要开源，**倾向 A**：仓库干净，使用者联网即可拉取。

## 3. 待决策事项（需要你拍板）

### 3.1 演示行为：按住说话之后做什么？

| 方案 | 行为 | 优点 | 缺点 |
| ---- | ---- | ---- | ---- |
| **A. 录音回放**（推荐） | 按住 BOOT 录音 → 松开自动播放刚才的录音 | 同时验证 ADC 和 DAC，逻辑闭环；不会啸叫 | 需要缓冲 |
| B. 实时直通 | 麦克风→扬声器实时回放 | 不需要缓冲，最简单 | 同板麦克风贴扬声器，**必然啸叫** |
| C. 录音存 TF 卡 | 按住录音写卡，松开从卡播放 | 时间不限（有卡时） | TF 卡还没到位，无法验证 |

推荐 **A**，并附加：开机播放一段提示音（验证 DAC 通路）、音量键调播放音量。

### 3.2 录音缓冲放哪？

| 方案 | 容量 | 需要改动 | 建议 |
| ---- | ---- | ---- | ---- |
| **启用 PSRAM（推荐）** | 8MB Octal | 打开 `CONFIG_SPIRAM*`（占 GPIO33~37，本板未使用） | ✅ 可录数十秒，为后续功能留空间 |
| 仅内部 RAM | ~150KB | 无 | 只能录 3 秒，体验差 |
| 降采样到 8kHz | 16KB/s | 改采样率 | 录音质量差，且违背 readme「24kHz」要求 |

推荐**启用 PSRAM**。风险：N16R8 是 Octal PSRAM，需 `CONFIG_SPIRAM_MODE_OCT` + 80MHz，配错会启动失败（可回滚）。

### 3.3 位宽：16bit 还是 24bit？

readme 写「codec 24bit」，但 **xiaozhi 同板实测用的是 16bit**（`I2S_DATA_BIT_WIDTH_16BIT`，ES8388 寄存器 `DACCONTROL1=0x18` 即 16bit I2S）。

建议 **16bit**：
- 语音场景 16bit 足够，信噪比已由 codec 模拟端决定
- Flash/RAM 占用减半，I2S 时序更容易稳
- 若确需 24bit，I2S 用 `I2S_DATA_BIT_WIDTH_24BIT` + `slot_bit_width=32`，ES8388 寄存器改 `0x00`，工作量不大但收益有限

### 3.4 LCD 是否同步显示音频状态？

目前 LCD 固定显示「时间 + SSID」。建议增加第三行/状态图标：`REC 00:05` / `PLAY` / `VOL 70`。

- 优点：功能串联完整，演示效果好
- 代价：需扩展 UI 状态接口（`lcd_ui` 暴露一个 set 接口，改动小）
- 注意：音频活跃时 LCD 仍是 20fps 整帧刷新，会与 I2S DMA 抢内存带宽，需实测有无爆音（见风险 §5.2）

### 3.5 采样率 24kHz 双向 vs 单向

`i2s_channel_init_std_mode` 在 xiaozhi 里 TX/RX 用**同一份配置**，要求输入输出采样率相同。readme 也是 24k/24k，一致 ✅。
但 ES8388 的 ADC 和 DAC 共用 LRCK，所以**无法同时用不同采样率**，这点已满足。

## 5. 风险与预案

### 5.1 ⚠️ ES8388 主从模式可能矛盾（最高风险）

xiaozhi 同板配置里：

```c
es8388_cfg.master_mode = true;          // 注释却写着 "CODEC IN I2S SLAVE MODE"
...
i2s_chan_config_t chan_cfg = { .role = I2S_ROLE_MASTER, ... };
```

ES8388 寄存器 0x08 bit7 定义为 1=master。**如果 codec 和 ESP32 都做 master，二者会同时驱动 BCLK/WS，形成总线争用**，表现为：无声、或声音断续、或电流异常。

**预案**：上板第一件事用逻辑分析仪看 BCLK 波形——若出现两个边沿打架/电平异常，把 `master_mode` 改为 `false`（codec 做 slave，由 ESP32 供时钟）再试。这是最可能出问题、也最容易踩坑的一处。

### 5.2 音频与 LCD/WiFi 争抢资源

| 冲突 | 现象 | 预案 |
| ---- | ---- | ---- |
| I2S DMA ↔ SPI DMA 抢带宽 | 播放爆音 | 降 LCD 刷新率到 10fps；或录音回放期间暂停 LCD 刷屏 |
| 音频任务优先级低 | 声音卡顿 | 音频任务优先级高于 LCD（当前 LCD=4，音频设 5~6），并绑 core 1 |
| WiFi 大流量 | 偶发爆音 | I2S 用足够大的 DMA 缓冲（`dma_desc_num`×`dma_frame_num`）抗抖动 |

### 5.3 功放使能极性与默认状态

readme 说 GPIO42 高电平开启。但 xiaozhi 这块板把 `pa_pin` 传的是 `GPIO_NUM_NC`，改用「耳机按键」手动控制 GPIO42（插耳机时打开）。

**预案**：按 readme 走（GPIO42 高=开），但初始化时先置低，等 ES8388 配置完成后再开，避免上电爆音。

### 5.4 上电/断电爆音

codec 上电顺序不当会有「啪」声。**预案**：先配 codec 寄存器 → 取消静音 → 再开 PA；断电前先静音再关 PA。

### 5.5 PSRAM 配置失败

`CONFIG_SPIRAM_MODE_OCT` 配错（比如实际是 Quad）会导致启动循环重启。**预案**：先在独立分支试，失败可回滚到「仅内部 RAM + 3 秒录音」的降级方案。

### 5.6 GPIO0/GPIO3 strapping 脚

按键接在 GPIO0 上，若按住上电会进下载模式；GPIO3 若有强下拉可能影响 JTAG 选择。**预案**：实测启动是否正常，必要时把耳机检测改为「上电后延时读取」。

## 6. 建议推进顺序

```
阶段 0（依赖+骨架）
   ↓  ← I2C 扫到 0x20 才继续
阶段 1（I2S 时钟+正弦波）
   ↓  ← 时钟正确才继续
阶段 2（ES8388 寄存器）  ← 主从模式在这里定案
   ↓
阶段 3（播放） → 阶段 4（录音） → 阶段 5（按键）
   ↓
阶段 6（集成 LCD/WiFi） → 阶段 7（文档）
```

**阶段 0~2 是最容易卡住的**（硬件通路 + codec 配置），建议每步都在串口打印清晰的检查点日志，一次上板就能定位问题在哪一层。阶段 3~5 在有声音之后都比较顺。
